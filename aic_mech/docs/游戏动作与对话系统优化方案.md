## 一、病人角色动作系统（2D 帧动画适配）

### 1.1 统一制作规格

| 项目 | 规格 | 说明 |
|---|---|---|
| 精灵尺寸 | **48×64 px**（1x 像素风基准） | 输出 @2x（96×128）与 @3x 适配高分屏 |
| 每动作帧数 | 4–7 帧（已定义在各病例 JSON `animation_states[].frames`） | 帧数越少循环越"卡通"，越多越流畅 |
| 播放帧率 | 循环动作 **8 fps**；一次性动作 **10 fps** | 单位帧时长 125ms / 100ms |
| 精灵表布局 | 横向单行排列，从左到右即播放顺序 | CSS `steps()` 直接驱动 |
| 朝向 | 默认正面 45° 微侧（对诊桌方向） | 后续可扩展左右行走帧 |
| 调色 | 每病人一个专属主色（见 1.3），面色层单独Overlay | 面色变化表现病情（蜡黄/潮红/发绀） |

### 1.2 动画状态机（代码级实现）

每个病例 JSON 的 `game_extensions.animation_states` 已含全部状态定义，前端只需实现一个通用状态机：

```js
// PatientSprite：数据驱动的帧动画状态机（直接可用）
class PatientSprite {
  constructor(caseData, spriteSheetUrl) {
    this.states = Object.fromEntries(
      caseData.game_extensions.animation_states.map(s => [s.state, s])
    );
    this.sheetUrl = spriteSheetUrl;   // 每个 case 一张精灵表
    this.current = null;
    this.el = document.getElementById('patientSprite');
  }
  play(stateId) {
    const s = this.states[stateId];
    if (!s || stateId === this.current?._stateId) return;   // 幂等
    this.current = { ...s, _stateId: stateId };
    const frameW = 48, dur = (s.loop ? 125 : 100);
    this.el.style.backgroundImage = `url(${this.sheetUrl})`;
    this.el.style.animation =
      `sprite-${s.frames}f ${dur * s.frames}ms steps(${s.frames}) ` +
      (s.loop ? 'infinite' : '1 forwards');
    // steps 关键帧由 buildKeyframes() 一次注入 <style>
  }
}
// CSS（模板，frames=N 时 background-position 从 0 到 -N*48px）：
// @keyframes sprite-6f { from {background-position: 0 0} to {background-position: -288px 0} }
```

**状态切换由游戏事件驱动**（触发条件已写进每个 `trigger` 字段）：

```
接诊进入 ──→ idle_normal
问诊某话题 ─┬→ 症状类话题 → 对应病征动画（sneeze / hold_belly_bend / shoulder_breath / hand_tremor / guard_rlq_bend）
            └→ 情绪类话题 → 人设动画（chat_gesture / anxious_fidget / phone_anxious）
执行治疗 ──→ 治疗动画（sip_orz_water / use_inhaler / eat_candy / postop_recovery）
治疗完成 ──→ 治愈动画（cured_cheer / cured_thumbsup / cured_relief / cured_pat_chest / cured_relax）→ 循环
病情恶化 ──→ 恶化动画（sway_dizzy 等，仅急症病例在延误时触发）
```

## 二、对话系统全面优化

### 2.1 对话五层结构（数据已就位）

每位病人的 `game_extensions.dialogue_layers` 均包含五层，游戏流程按层取用：

| 层 | 字段 | 触发时机 | 呈现方式 |
|---|---|---|---|
| L1 初始对话 | `greeting` | 进入诊室 | 顶部立绘气泡，逐字打出 |
| L2 问诊对话 | `inquiry.症状/诱因/既往史/伴随症状` | 点击问诊话题按钮 | 情绪前缀驱动表情与语气 |
| L3 误诊反馈 | `misdiagnosis_feedback.{易错病名}` | 确诊选错时 | **双气泡**：系统教学卡(蓝) + 病人反应(角色色) |
| L4 治疗反馈 | `correct_treatment_feedback` | 每个正确治疗步骤完成 | 气泡 + 状态提示条联动 |
| L5 治愈结语 | `cure_farewell` | 治疗完成 | 演出模式：治愈动画 + 结语 + 结算卡 |

### 2.2 情绪文本驱动（代码级实现）

所有文案自带 `(情绪)` 前缀，渲染时解析为立绘表情与气泡样式：

```js
const EMOTION_STYLE = {
  '虚弱地': {cls:'bubble-weak',  face:'face-pain',    shake:0},
  '断断续续':{cls:'bubble-breath',face:'face-breathe', shake:0, charDelay:160}, // 哮喘专用慢速逐字
  '急切地': {cls:'bubble-urgent',face:'face-urgent',  shake:1},
  '絮叨地': {cls:'bubble-chat',  face:'face-happy',   charDelay:30},
  '嘴硬':   {cls:'bubble-stub',  face:'face-smirk',   shake:0},
  '理直气壮':{cls:'bubble-bold',  face:'face-proud',   shake:1},
  '系统':   {cls:'bubble-system',face:null}
};
function renderDialogue(text) {
  const m = text.match(/^\(([^)]+)\)\s*(.*)$/s);       // 剥离情绪前缀
  const style = m ? (EMOTION_STYLE[m[1]] || {charDelay:60}) : {charDelay:60};
  const body  = m ? m[2] : text;
  // 逐字机 + 气泡样式 + 立绘表情切换（style.face 可直接映射立绘帧）
  return {body, ...style};
}
```

**语气差异化已内置**（无需二次创作）：王秀兰絮叨拖长音 / 林浩嘴硬自嘲 / 陈小雨短句气声（charDelay 加慢表现喘息）/ 赵国栋倔强命令式 / 周子昂职场黑话语速快。

### 2.3 问诊话题按钮与信任度联动

- 问诊话题固定四键：`症状 / 诱因 / 既往史 / 伴随症状`（各病人回答已备好，含教学彩蛋）。
- **信任度**沿用现有 0–1 数值：重复粗暴追问（连续 3 次跳过安抚直接问既往史）→ 触发 `dialogue_scripts.trust_low`；先行安抚/解释 → `trust_high`，并解锁 `persona` 完整背景闲聊（chat_gesture 等人设动画此时才播放）。
- 误诊反馈层**永不惩罚性扣血**：每次误诊都是一张"鉴别卡"，鼓励学生把三个易错病都试一遍（对应说明书卡1–卡5 的鉴别要点，形成学习闭环）。

## 三、游戏整体观赏性提升

### 3.1 病情状态文字提示条（状态机联动）

顶部常驻"病情播报条"，文案直接取 `game_extensions.status_hints`（初始/治疗后/治愈三段已写好）：

```
【状态提示】SpO₂ 93% · 讲话成短句 · 端坐撑膝 —— 中度发作，吸入治疗刻不容缓
```

实现：监听遥测/治疗事件 → 查表换文案 → 颜色分级（白→黄→红→绿）。呼吸/心率数值可直接复用现有监护仪 Canvas。

### 3.2 治疗成功/失败反馈

| 场景 | 呈现 |
|---|---|
| 正确治疗步骤 | 病人 L4 反馈气泡 + 状态条变绿 + 轻快"叮"音效 + 头顶 ✓ 粒子 |
| 触碰禁忌红线 | 全屏红闪 0.3s + 警报音 + 弹出**禁忌卡**（取 `treatment_plan.contraindications` 原文）+ 护士角色立绘摇头 |
| 病情延误恶化（急症） | 屏幕边缘暗角脉动 + 病人切换恶化动画（sway_dizzy 等）+ 状态条变红闪烁 |
| 治愈结算 | 演出模式：治愈动画 → L5 结语 → 六维雷达结算卡 + 一句"复盘金句"（取说明书对应速查卡名） |

### 3.3 轻剧情背景卡（入场演出）

接诊前 3 秒展示**背景故事卡**（取 `game_extensions.backstory`，已含人物钩子与"治愈关键"悬念），像素立绘 + 打字机文本 + 轻音乐。让每位病人先是一个"人"，再是一份"病历"。

### 3.4 诊室氛围细节（像素点睛，工作量小效果好）

- 候诊屏滚动显示 `index.json` 的 `one_liner`（下一个病人的趣味预告）；
- 每位病人入场携带专属道具：手绢 / 外卖盒 / 速写本+猫毛 / 太极扇 / 格子衫双肩包（与动画剪影一致）；
- 治愈后诊室墙上贴一颗星，集齐 5 星解锁高阶隐藏病例（孙建国）；
- 全场景统一 2x 像素渲染（`image-rendering: pixelated`），配色低饱和暖色，符合轻松教学调性。

### 3.5 数据接入改造（对现有 game.js 的最小改动清单）

1. `game.js` 顶部硬编码的角色名映射（`患者 · 孙建国` 等）改为从病例 JSON `patient_profile` 读取；
2. `/api/case/start` 的 `case_id` 改为从 `cases/index.json` 选择的当前病例（后端路由暂仍以 `case_chest_pain_001` 引擎运行，数据侧已就绪，多病例引擎接线为后续工程项）；
3. 问诊/检查/治疗按钮的文案与判定表，从对应病例 JSON 的 `required_exams / treatment_plan.steps / decoy_diagnoses` 生成——**前端不再手写任何病例文本**。
